# Chapter 03 - Identifiers & Literals (Naming Things in Code)

---

## What This Chapter Is

Every programming language has rules for naming things (identifiers) and representing raw data (literals). This chapter covers JavaScript's naming conventions and syntax for leaving notes (comments) in your code. It also includes keyboard shortcut references for VS Code.

---

## Files in This Chapter

### 06_Identifiers_Rules.js
Covers JavaScript identifier naming rules:
- Valid characters: letters (a-z, A-Z), `$`, `_`
- Cannot start with a digit
- Cannot use reserved keywords (`if`, `for`, `while`, etc.)
- Case-sensitive: `Rock` and `rock` are different identifiers
- Unicode characters are supported (e.g., `espanol`, `中文`)

Naming conventions:
- **camelCase**: `myBigRock`
- **PascalCase**: `MyBigRock`
- **UPPER_SNAKE**: `BIG_ROCK`

Additional practice with identifier naming.

### 08_Comments.js

- `//` — Single-line comment
- `/* */` — Multi-line comment
- `/** */` — JSDoc documentation comment

## Why This Matters

Good naming makes code readable and maintainable. Descriptive names communicate intent. Comments explain why code exists, which is just as important as what the code does.

---

## What You'll Learn

- Rules for naming JavaScript identifiers
- Naming conventions (camelCase, PascalCase, UPPER_SNAKE)
- Writing single-line, multi-line, and JSDoc comments
- VS Code keyboard shortcuts for faster editing

---

## Key Terms

| Term | Definition |
|---|---|
| Identifier | The name of a variable, function, or other entity |
| Literal | A raw value like `5` or `"cat"` |
| Comment | Human-readable text ignored by the interpreter |
| CamelCase | Words joined with internal capitalization after the first word |
| PascalCase | Words joined with each word capitalized |
